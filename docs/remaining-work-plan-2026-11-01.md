## 지금까지 반영한 변경

- `f62d802`: ZIP 업로드는 GPU 상태로 막지 않고 CPU API에 실제 ZIP을 전송한다. 서버 응답의 게시물·추천 사진 데이터를 화면에 연결한다.
- `02fe95a`: 썸네일 캐시가 실패해도 서버 썸네일 URL로 대체한다. 캡션/해시태그 후보 점수가 높은 게시물을 사진 선택 한도 안에서 우선 고르되, 한 게시물의 여러 사진이 다른 후보 게시물을 밀어내지 않도록 대표 사진을 먼저 선택한다.

## 구현 상태 점검

- Instagram ZIP 파서는 `posts_*.json` 형식을 우선 지원하고, JSON이 없는 최신 내보내기는 `your_instagram_activity/media/posts_*.html`의 게시물 카드와 연결된 이미지 파일을 읽는다. 영상은 제외한다.
- UC1 API는 게시물별 캡션/해시태그 후보와 썸네일 URL을 반환한다. 사용자가 선택한 사진만 GPU 분석 작업으로 전달한다.
- 사진 선택 UI는 API 응답의 `recommended_photo_ids`를 사용한다. 서버 추천 점수는 캡션/해시태그 후보에 기반한 1차 정렬이며, 이미지의 실제 위험 판단은 선택 후 OCR/VLM 분석에서 한다.
- 사용자 세션은 서명된 HttpOnly 쿠키로 브라우저별 작업을 나누지만, 계정 로그인은 아니다. UC1 업로드 파일은 완료·실패·취소·TTL 때 지운다.
- 외부용 API/서비스 계정 체계, 다중 CPU 워커의 영속 큐/DB, WebRTC 직접 연결은 아직 구현 범위 밖이다.

## 진행 계획

1. **GitHub 인증을 복구하고 PR #8 갱신**: 로컬 커밋 `f62d802`, `02fe95a` 및 이 현황 문서를 origin 브랜치에 반영한다. CI 결과와 PR 파일 목록을 확인한다.
2. **NCP 배포**: 임시 SSH 공개키를 CPU/GPU 서버에 등록한 뒤 최신 패키지를 CPU에 적용한다. 모델 서비스는 설정을 바꾸지 않고 health/status를 확인한다. 프론트 번들 해시가 최신인지 확인한다.
3. **외부 HTTPS 구성**: 사용자가 소유한 도메인과 DNS 제어 권한을 확보하고 NCP 콘솔에서 인증서·Public ALB·Target Group·ACG·Listener ACL을 구성한다. 외부 브라우저에서 `/health`, `/api/status`, ZIP 업로드 진입을 확인한다.
4. **사용자 실사진 시나리오 확인**: 사용자가 실제 Instagram ZIP을 올려 사진 썸네일, 위험 후보 게시물의 기본 선택, 후보 토글, 분석 결과 게시물 그룹화를 직접 확인한다. 실패가 있으면 식별자/상태코드만으로 원인을 좁히고 사진·OCR 본문은 로그에 남기지 않는다.
5. **제한 공개 보강**: 외부 사용자가 늘기 전에 로그인, 업로드별 바이트/횟수 제한, 취소/만료 정리, 큐 포화 안내를 적용한다.
6. **WebRTC 여부 결정**: ALB를 통한 HTTPS가 허용되면 현재 아키텍처를 유지한다. 이미지 데이터가 반드시 중계를 피해야 하는 요구가 확정되면 signaling/WebRTC를 별도 설계·비용/도달성 평가 후 구현한다.

## 지금 필요한 외부 입력

- GitHub에 푸시하기 위한 GitHub 인증 세션 복구. 토큰/비밀번호를 채팅에 입력하지 않는다.
- NCP 접속을 위한 임시 공개키 등록 또는 기존 로그인 터미널의 배포 실행 가능 여부.
- HTTPS 주소용 도메인과 NCP DNS 레코드 제어 권한.
- 외부 시범 사용자 접근을 제한할 테스트 공인 IP 목록.
