# 운영 로그

CPU API는 사용자 작업 이력을 숫자만 담은 JSONL로 기록합니다. 기본 파일은 `backend/logs/audit.jsonl`이고, 디렉터리 권한은 `0700`, 파일 권한은 `0600`으로 설정합니다. 파일이 5 MiB에 도달하면 회전하며 현재 파일과 최대 3개 백업만 유지합니다.

기록 이벤트는 연결 생성/명시적 해제, ZIP 업로드 성공(게시물·사진 수), UC1 분석 완료/실패(사진·검출·실패 수), UC2 사진 진단(검출·경고 수), 마스킹 재검사(영역·잔여 OCR 줄·조각 수), 가린 사진 다운로드 시작(사진·선택 영역 수)입니다. 브라우저를 닫은 사실은 웹 앱이 신뢰성 있게 감지할 수 없으므로, 연결 해제는 개인정보 처리방침 화면의 **서버 연결 해제** 버튼을 눌렀을 때 기록합니다.

로그에는 사진 바이트, 이름, 캡션, OCR/VLM 문구, 파일명, IP, 쿠키, 세션 ID, 원본 요청 본문을 기록하지 않습니다. 로그 쓰기는 허용 목록에 있는 이벤트와 정수 카운트만 받습니다. Uvicorn 접근 기록도 앱에서 비활성화되어 있습니다.

## 로그 조회

1. CPU 서버 `.env`에 최소 32자 이상의 임의 비밀값으로 `AUDIT_VIEW_TOKEN`을 설정합니다. 예: `openssl rand -hex 32`로 생성합니다.
2. CPU API를 재시작합니다.
3. 웹 앱의 개인정보 처리방침에서 **운영 로그 보기**를 열고 조회 키를 입력합니다. 키는 브라우저 메모리에만 두며 서버 요청 헤더로만 전달합니다.

조회 API는 `GET /api/admin/audit?limit=100`이며 `X-Audit-Token` 헤더가 필요합니다. 응답은 최신 1~500개의 allowlisted 이벤트입니다. 운영 로그 기능은 단일 CPU worker를 전제로 합니다.
