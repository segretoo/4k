# 데이터·보안 원칙 (반드시 지킴 · v2.0)

1. **실제 아이 사진 금지.** 시연은 소품(가짜 이름표·원복)과 가상 계정·가상 캡션만 사용합니다.
2. **GPU 서버에 개인정보 업로드 금지** (대회 규정).
3. **API 키는 저장소에 넣지 않습니다.** `.env`만 사용, `.env.example`만 커밋.
4. **본인 데이터만 분석.** 계정 URL·커뮤니티 주소·타인 계정 입력은 받지 않습니다 (아이 정보 수집 도구로 악용 방지, 제3자 정보 수집·스크래핑 금지).
5. **얼굴 인식·얼굴 변형 기능 없음.**
6. **자동 삭제·자동 게시 없음.** 삭제 전 비공개 전환을 먼저 권장합니다.
7. **사실만 제출.** 발표·문서의 수치는 실제 측정값만 씁니다 (서약서 허위사실 조항).
8. 원본 사진은 외부 API로 보내지 않습니다. 외부 API를 쓰게 되면 resources.md와 발표에 공개합니다.
9. GPU 서버는 11/1 13:00에 삭제되므로 그 전에 결과·로그를 백업합니다 (`scripts/backup.sh`).
10. **동의 먼저.** 개인정보 수집·이용 동의 + 보호자(법정대리인) 확인, 두 필수 동의 없이는 분석하지 않습니다. 동의 화면의 보관·삭제 문구는 실제 구현과 같아야 합니다.
11. **내보내기 파일은 게시물만 읽습니다.** DM·댓글·팔로워 등 다른 폴더는 열지 않고 바로 버립니다.
12. **선택한 글자 영역만 주변 평균색과 부드러운 경계로 가립니다.** 서버는 patch와 alpha만 반환하며, 브라우저가 원본 해상도에 합성해 새 JPEG를 만듭니다. 새 파일은 EXIF/GPS 메타데이터 없이 저장하고, 선택한 글자가 재검사에서 읽히면 저장을 막습니다. OCR로 확인할 수 없는 위치는 사용자가 사진을 직접 확인해야 합니다.
13. **위험 단계는 규칙 코드로 계산합니다.** 발표·화면의 단계와 근거는 규칙 결과 그대로 씁니다.
14. **요청은 브라우저 세션 단위로 구분합니다.** 서버가 서명한 HttpOnly 쿠키에서 소유자를 계산하며, 업로드·작업 ID만 아는 다른 세션은 접근할 수 없습니다. 로그인 계정이 도입되면 계정 인증을 이 세션에 연결합니다.
15. **GPU는 단일 모델 슬롯과 공정한 제한 대기열을 씁니다.** 한 번에 한 장만 추론하고, 대기열은 최대 4개이며 각 브라우저는 대기 요청을 1개까지만 가질 수 있습니다. 자리가 없으면 HTTP 429를 돌려 보내 재시도하게 합니다.
16. **UC2 사진은 애플리케이션에서 파일로 저장하지 않습니다.** 업로드를 검증·분석한 뒤 요청 메모리가 회수되며, OS의 임시 업로드 스풀은 닫습니다. UC1 ZIP/사진은 권한이 제한된 세션 폴더에만 두고 완료·취소·만료·재시작 때 삭제합니다. 일반 디스크 파일 삭제는 복구 불가능한 완전 삭제를 보장하지 않습니다.
17. **tmpfs는 RAM 여유와 동시 업로드 상한을 확인한 뒤에만 씁니다.** CPU 서버는 RAM 8GB, 스왑 없음이며 UC1 압축 해제 제한이 1.5GB라서 무제한 RAM 파일시스템을 설정하지 않습니다. 메모리 덤프·스왑·임시 스풀 정책도 함께 관리합니다.
